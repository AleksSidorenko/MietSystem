MietSystem

Full-featured backend for housing rentals in Germany

Project Description

MietSystem is a full-featured backend service for housing rentals in Germany, developed using the Python, Django and Django REST Framework stack.

🏠

Listing Management

CRUD operations for landlords and tenants with a complete permissions system

🔍

Search & Filtering

Full-text search, filters by price, location and attributes

👥

Role System

Tenant, Landlord, Administrator with clear role separation

📅

Booking

Booking system with availability checks and notifications

⭐

Reviews & Ratings

Rating and review system after booking completion

🌐

Localization / I18n

Supports German, English and Russian

Architecture

Modular monolith — the project is split into independent Django apps for better code organization and potential future scaling into microservices.

users

Authentication, roles, user profiles

listings

Property listings, CRUD operations

bookings

Booking system with date checks

reviews

Reviews and ratings for listings

locations

Geographic data and geocoding

analytics

View statistics and popularity

core

Core settings and configuration

utils

Utility helpers and permissions

Key Features

🔐

Security

JWT authentication, CSRF protection, brute-force protection (django-axes), DDoS mitigation (django-ratelimit). Passwords are hashed with Argon2.

⚡

Performance

Redis caching for popular listings, Celery for asynchronous tasks, MySQL indexes for fast search.

📊

Analytics

Tracking view and search history, computing listing popularity with formula: views×0.3 + reviews×0.5 + time_decay×0.2

🌍

Geocoding

Integration with OpenStreetMap to automatically determine address coordinates via Celery tasks.

📧

Notifications

Email notifications on bookings, confirmations and reviews via asynchronous Celery tasks.

🛠️

API Documentation

Swagger/Redoc for interactive API documentation, Postman collections for testing.

Role and permission system

  • Tenant (IsTenant): can create bookings and reviews, and view listings
  • Landlord (IsLandlord): can create and edit only their own listings and confirm bookings
  • Administrator (IsAdmin): full access to all resources via the Django admin panel

Main challenges and findings

🔐 Designing the role and permission system

The toughest task was segregating tenant, landlord and administrator permissions while supporting multiple roles. Solution: custom DRF permissions + standard Django groups.

🔄 Configuring asynchronous tasks with Celery

Integrating Celery with RabbitMQ and Docker required careful config. Finding: asynchrony greatly improves performance but requires monitoring.

🌍 Localization and multilingual support

Using django-modeltranslation automatically adds suffixes (_de, _en) to DB fields. Consider moving translatable fields into separate models in the future.

🛠️ Setting up the API with Django REST Framework

Reviewing serializers, viewsets and routers for CRUD with pagination and filters. Finding: DRF simplifies REST but requires precise permission configuration.

⚡ Ensuring security

JWT authentication, CSRF protection, brute-force protection (django-axes), DDoS mitigation (django-ratelimit). Use Argon2 for password hashing.

🐳 Containerization and deployment

Configuring Dockerfile and docker-compose.yml for production, including collectstatic, environment variables and AWS integration.
